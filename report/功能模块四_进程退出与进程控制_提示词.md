- `schedule()` 先清除 `current->need_resched`，再从 `current->list_link` 起查找可运行进程，找不到时退回 `idleproc`，必要时调用 `proc_run()` 切换页表与上下文。

- `trap()` 在用户态返回前检查：`current->flags & PF_EXITING` 时调用 `do_exit(-E_KILLED)`；`current->need_resched` 时调用 `schedule()`。因此 `do_yield()` 与 `do_kill()` 不应自行切换进程。

- `do_wait()` 已实现：在 `WT_CHILD` 下睡眠并在唤醒后重新扫描，发现 `PF_EXITING` 时调用 `do_exit(-E_KILLED)`；回收僵尸时读取 `exit_code`，再 `unhash_proc()`、`remove_links()`、`put_kstack()`、`kfree()`。

## 2. 模块二的回收契约（必须匹配）

- 退出方负责：解除 mm 引用、按引用计数释放地址空间、写入 `exit_code`、进入 `PROC_ZOMBIE`、把孤儿交给 `initproc`、唤醒等待子进程的父进程。
- 等待方负责：从散列表与进程链表摘除僵尸、回收内核栈与 PCB。
- 双方共同依赖 `WT_CHILD` 作为“本进程正在等待子进程状态变化”的标记；`wakeup_proc()` 已负责清除等待状态，不要手写状态清除。
- `init_main()` 在全部用户进程结束后断言 `initproc->cptr == NULL`、`nr_process == 2`、内核分配量回到基线、空闲页差值与 SLOB 持有页增量一致，并输出 `init check memory pass.`。任何未回收的用户页、页表页或 VMA 都会使该检查失败，因此 `do_exit()` 必须把 mm 侧资源释放干净，同时不得越权释放 PCB 与内核栈。

## 3. 用户程序与评分要求

- `user/exit.c`：子进程 `exit(magic)` 后父进程 `waitpid(pid, &code)` 必须成功且 `code == magic`，随后再次 `waitpid` 必须失败。
- `user/spin.c`：父进程 `kill(pid)` 必须返回 0，随后 `waitpid(pid, NULL)` 必须返回 0，且整个系统在 `init check memory pass.` 前不 panic。
- `user/yield.c`：多次 `yield()` 后仍能继续执行，`need_resched` 的置位不能破坏返回现场。
- `user/forktest.c`：大量子进程 `exit` 与 `wait` 交错，不能出现僵尸无人回收、空闲页泄漏或 `nr_process` 计数错误。
- `user/waitkill.c`：被 `kill()` 的睡眠进程必须能被唤醒并沿 `PF_EXITING` 路径退出，不能永远睡眠。
- `tools/test_lab5.c` 的 `test_lab5_process_control()` 在 `init_main()` 开头注入，断言 `do_yield() == 0 && current->need_resched`、`do_kill(-1) == -E_INVAL`、`do_wait(-1, NULL) == -E_BAD_PROC`。
- `tools/grade.sh` 的 `exit`、`spin`、`yield`、`forktest` 等用例要求不出现 `user panic`，并输出 `init check memory pass.`。

## 1. do_exit

**Pre-Condition：** `current != NULL` 且不是 `idleproc`、`initproc`；`current` 可以持有独占或共享的 mm，也可以是 `mm == NULL` 的内核线程。

**Post-Condition：** 当前进程的用户地址空间已按引用计数释放或解除，`exit_code` 已发布，状态为 `PROC_ZOMBIE`，子进程已转交 `initproc`，父进程在等待子进程时被唤醒，随后调度离开且永不返回。

**Case 1：非法退出者。** `current == idleproc` 或 `current == initproc` 时通过 `panic()` 明确报告，不允许其进入僵尸态；不要只返回值后继续执行。

**Case 2：持有用户地址空间。** 在仍然有效的状态下先完成 mm 侧的解除与释放，再发布僵尸态：切回 `boot_pgdir_pa` 并 `flush_tlb()`，更新 `current->pgdir`，把 `current->mm` 置空；`mm_count_dec()` 减到 0 时依次执行 `exit_mmap()`、`put_pgdir()`、`mm_destroy()`，减后非 0 时只解除本进程的引用。共享地址空间（`CLONE_VM`）不得被单个退出者销毁。

**Case 3：内核线程退出。** `current->mm == NULL` 时跳过地址空间处理，只完成状态发布、孤儿收养与唤醒。

**Case 4：父进程与子进程。** 在中断保护下：写入 `exit_code`、设置 `PROC_ZOMBIE`；若 `current->parent->wait_state == WT_CHILD`，唤醒父进程；把 `current->cptr` 起的全部子进程逐个改挂到 `initproc`，维护 `parent`、`cptr/optr/yptr` 指针；若被转交的子进程已经是 `PROC_ZOMBIE` 且 `initproc` 正在 `WT_CHILD` 等待，唤醒 `initproc`。唤醒必须复用 `wakeup_proc()`，不要手写状态与 `wait_state` 更新。

**Case 5：调度离开。** 在中断关闭状态下调用 `schedule()`，返回则 `panic()`，因为死亡进程不应被再次调度。不得在本函数中回收自身内核栈、PCB，也不得摘除自身散列与链表节点。

**Requirements：**

- 资源释放与僵尸发布之间不得出现“父进程已可回收 PCB，而本进程仍在继续使用内核栈”的窗口；推荐顺序为：先完成 mm 解除/释放，再在同一临界区发布 `exit_code` 与 `PROC_ZOMBIE`、收养孤儿、唤醒等待者，随后直接 `schedule()`。
- 释放地址空间前必须已经离开旧页表，不能在自己仍使用的用户页表上执行 `exit_mmap()` 与 `put_pgdir()`。
- 不得重复调用 `remove_links()` / `unhash_proc()`，不得直接修改 `nr_process`。
- 不得把 `PF_EXITING` 当成“已经退出”，僵尸态只由 `PROC_ZOMBIE` 表示。
- `exit_code` 的写入必须先于父进程唤醒，保证 `do_wait()` 读到的退出码正确。
- 不修改 `trap()`、`do_wait()`、`do_fork()` 或调度器来迁就本函数。

## 2. do_yield

**Pre-Condition：** `current` 有效且处于可运行状态。

**Post-Condition：** 当前进程的 `need_resched` 被置位，函数返回 0；当前进程状态、`wait_state`、页表与上下文均不改变。

**Requirements：**

- 只发布重新调度请求，由 `trap()` 的返回路径或显式调用者决定何时 `schedule()`；本函数不直接切换进程。
- 不修改 `state`、不调用 `wakeup_proc()`、不清零其他进程的 `need_resched`。
- 不使用会阻塞或睡眠的接口，不引入新的临界区依赖；置位动作需对调度器可见。

## 3. do_kill

**Pre-Condition：** `pid` 来自不可信的用户输入；目标可能不存在、正在运行、正在睡眠或已经退出。

**Post-Condition：** 目标被标记 `PF_EXITING` 并在必要时被唤醒；返回值准确反映本次操作结果，不留下部分修改。

**Case 1：PID 非法或目标不存在。** `find_proc()` 返回 `NULL`（包括 `pid <= 0`、超过 `MAX_PID`）时返回 `-E_INVAL`。

**Case 2：目标已处于退出流程。** `flags & PF_EXITING` 已置位时返回 `-E_KILLED`，不重复唤醒。

**Case 3：目标正常。** 在中断保护下置位 `PF_EXITING`；若目标处于 `PROC_SLEEPING` 且 `wait_state` 含 `WT_INTERRUPTED`（`WT_CHILD` 已包含该位），调用 `wakeup_proc()` 使其重新进入调度并沿 `PF_EXITING` 路径退出；对 `PROC_RUNNABLE` 的目标不重复唤醒，避免 `wakeup_proc()` 的重复唤醒告警；对 `PROC_ZOMBIE` 目标不调用 `wakeup_proc()`，避免触发断言。成功返回 0。

**Case 4：目标是自身。** 允许置位并返回 0，由 `trap()` 的用户态返回路径调用 `do_exit(-E_KILLED)`；不得在 `do_kill()` 内直接退出或直接调度。

**Requirements：**

- 查找目标、检查标志、置位、判断唤醒条件必须在同一个中断保护区间内完成，避免与 `do_fork()` 的散列插入、`do_wait()` 的摘除并发交叉。
- 退出意图只通过 `PF_EXITING` 表达，不直接修改目标状态为 `PROC_ZOMBIE`，不代替目标执行资源回收。
- 不向目标写入 `exit_code`，该值由目标自己的 `do_exit()` 写入；被杀死进程的退出码由调用方通过 `do_exit(-E_KILLED)` 决定。
- 不使用 `do_kill()` 唤醒正在 `WT_CHILD` 之外等待的无关进程，唤醒条件必须与目标 `wait_state` 一致。

## 4. 与调度器、等待路径的一致性

**Pre-Condition：** 调度器可能在任意中断返回点接管 CPU；`do_wait()` 可能在被唤醒后重新扫描子进程。

**Post-Condition：** 三个函数的所有状态转换都能被 `schedule()`、`do_wait()`、`trap()` 正确观察，不出现“状态已改但资源未处理”或“资源已释放但状态仍可运行”的中间态。

**Requirements：**

- `do_exit()` 发布 `PROC_ZOMBIE` 后不得再被调度执行；`do_wait()` 只回收僵尸，不回收仍可运行的进程。
- `do_kill()` 唤醒的睡眠进程若在 `do_wait()` 中，`do_wait()` 会检查 `PF_EXITING` 并调用 `do_exit(-E_KILLED)`，本模块不得抢先替它退出。
- `do_yield()` 只影响 `need_resched`，与 `trap()` 的调度时机保持一致，不与 `wakeup_proc()` 的 `wait_state` 语义混用。
- 所有 `local_intr_save()` 必须配对 `local_intr_restore()`，临界区内不得调用可能睡眠或长时间阻塞的接口。
